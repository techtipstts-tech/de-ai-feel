# de-ai-feel：去 AI 感檢查層

一個 Claude Code skill，專門抓「一看就是 AI 寫的」那種味道，抓完告訴你怎麼修，修完讀起來像台灣真人在講話。

我自己做內容行銷，每天大量用 AI 產草稿。用久了發現一件事：AI 寫的東西會露餡，而且露餡的地方高度重複。與其每次靠語感亂改，我把這些露餡點一條一條記下來、分類、驗證，磨了很久才長成現在這份資料庫。它不負責寫，負責抓。

## 這東西為什麼有用

多數「去 AI 味」的教學只給你一句「寫自然一點」，等於沒說。這份 skill 把問題拆到可以操作的層級：

- **18 條病症，每條都有「症狀、為什麼像 AI、怎麼修」**。看得懂病因，才改得動。
- **每條病症附「誤殺邊界」**。這是我踩過最多坑的地方：改過頭比不改更慘。比如「三點式結構」是病，但內容真的有三個獨立點就該放行；「總結收尾」是病，但全文最後收一次沒問題。邊界寫死，執行的人（或 AI）不用搖擺。
- **保護清單機制**。去 AI 感最大的風險是把事實一起改掉。價格、數字、專有名詞、引號原話、承諾條款，改稿前先圈起來，改完逐項回讀。「42%」不能漂移成「超過四成」。
- **50 組以上中國用語對照表**。AI 的中文語料以簡體為大宗，輸出繁體字時用語常常還是中國的（視頻、質量、信息）。對照表之外還有語境判斷詞（優化、文檔這種不能一刀切的）、量詞慣用法、全形標點規則。
- **工具痕跡偵測**。`utm_source=chatgpt.com`、`turn0search0` 殘碼、「以下是清理後的版本」這種對話框殘留，都是用了 AI 且沒校對的鐵證，優先清。
- **流行語加料判斷層**。台味流行語是調味料，一篇 0 到 1 個剛好。內建三個 gate（人設合不合、內容類型合不合、詞還在不在流行期）幫你判斷該不該加、加在哪。
- **發文前自檢清單**。17 個檢查點逐條掃，最後一招是把整篇唸出來，唸起來卡的地方就是 AI 感所在。

## 我做了什麼分析

這份資料庫的內容來自幾個方向的累積：

1. **先拆根源**。AI 感的本質是「沒有個人特徵的平均值」：對齊訓練把模型調得太乖、統計平均化讓它輸出最安全的講法、不敢下判斷、加上英翻中的翻譯腔骨架。搞懂這四個根源，修法的方向就定了：更具體、更敢、更口語、更台。
2. **大量對比 AI 稿與真人稿**，把重複出現的露餡點歸納成 18 條病症，分成結構病、句型病、用詞病、內容病、工具痕跡病五類。
3. **反覆驗證誤殺邊界**。每條病症都在實際改稿中測過「什麼情況其實不算病」，才敢把邊界寫進去。
4. **吸收開源專案與寫作教材**。中國用語對照與工具痕跡偵測的部分設計參考了 speak-human-tw（MIT License），另外融入了動詞精準化、鉤子開頭、焦點法則這些傳統寫作技法，讓 skill 除了抓病還能把「沒病但平庸」的稿往上推。
5. **在自己的社群內容產線上長期實戰**，發文前都過這層檢查，發現新的露餡點就補進資料庫。它一直在長大。

## 怎麼安裝

這是 Claude Code 的 skill。把整個資料夾放進你的 skills 目錄：

```bash
git clone https://github.com/techtipstts-tech/de-ai-feel.git ~/.claude/skills/de-ai-feel
```

重開 Claude Code session 就能用。不用 Claude Code 的人也可以直接把 `SKILL.md` 全文貼給任何 AI 當 system prompt 或檢查指令，一樣有效。

## 怎麼用

四種用法：

- **當檢查層**：任何寫作流程產完稿，丟給它掃一遍再輸出。可以掛在其他寫作 skill 後面當最後一道品質關卡。
- **當改稿指令**：丟一篇稿說「用 de-ai-feel 幫我抓 AI 感」，它會逐條標出病症加給修法。
- **當加料判斷**：問「這篇適合加流行語嗎」，它套三個 gate 和用量表回答。
- **當教學**：想理解「這句為什麼像 AI」，直接查病症資料庫那節。
